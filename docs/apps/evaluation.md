# 평가와 벤치마크

!!! basic "한눈에 보기"
    "이 모델이 더 좋다"는 말은 무엇으로 증명할까요? **벤치마크**는 모두가 같은 문제로 치르는 표준 시험입니다. 수학, 코딩, 과학 지식, 긴 글 이해 등 분야별 시험이 있고, 점수로 모델을 비교합니다.

    하지만 시험 점수에는 함정이 있습니다.

    - **기출 유출**: 시험 문제가 학습 데이터에 섞이면 외워서 맞힙니다(**오염**).
    - **천장 효과**: 모든 모델이 90점을 넘으면 더 이상 차이를 구별하지 못합니다(**포화**). 그래서 점점 어려운 시험이 새로 나옵니다.
    - **운**: 문제 수가 적으면 1–2점 차이는 우연일 수 있습니다.
    - **현실과의 차이**: 시험을 잘 보는 것과 실제 업무를 잘하는 것은 다릅니다.

    그래서 실무에서는 공개 벤치마크로 후보를 좁히고, **내 용도에 맞는 자체 평가 세트**로 최종 결정을 내립니다.

## 평가 방식 { .l2 }

| 방식 | 방법 | 장점 | 단점 |
|---|---|---|---|
| 정답 비교 | 객관식, 숫자 정답, 정확 일치 | 자동, 재현 가능 | 열린 답변에 못 씀 |
| 실행 검증 | 코드 테스트, 수학 검증기, 환경에서의 작업 성공 | 객관적 | 환경 구축 비용 |
| LLM 심판 | 다른 LLM이 기준표(rubric)로 채점 | 열린 답변 자동 평가, 저렴 | 긴 답 선호, 자기 모델 선호 등 편향 |
| 사람 평가 | 전문가 채점, 두 답 중 선택 | 실제 선호에 가장 가까움 | 비싸고 느림, 평가자 간 불일치 |
| 쌍대 비교 리더보드 | 사용자가 익명 두 모델 답 중 선택 → Elo/Bradley-Terry 점수 | 대규모 실사용 선호 | 말투·길이·서식에 끌림, 질문 분포 치우침 |

## 코드로 보기 { .l2 }

두 가지를 봅니다. ① 문항 500개짜리 시험에서 두 모델의 점수 차이가 **우연인지** 부트스트랩 신뢰구간으로 확인하고, ② 사람의 쌍대 선택 결과로 **Elo 점수**를 매깁니다.

```python
import numpy as np
rng = np.random.default_rng(0)
a = rng.random(500) < 0.72           # 모델 A: 500문항 정답 여부 (가상)
b = rng.random(500) < 0.69           # 모델 B
print("A", a.mean(), "B", b.mean(), "차이", round(float(a.mean() - b.mean()), 3))

idx = rng.integers(0, 500, size=(10_000, 500))     # 문항을 복원추출해 1만 번 재계산
diff = a[idx].mean(1) - b[idx].mean(1)
lo, hi = np.percentile(diff, [2.5, 97.5])
print(f"차이의 95% 신뢰구간: [{lo:.3f}, {hi:.3f}]")

# 쌍대 비교(사람이 둘 중 나은 답을 고름)로 Elo 점수 매기기
true = {"A": 1100, "B": 1000, "C": 950}
elo = {m: 1000.0 for m in true}
names = list(true)
for _ in range(6000):
    x, y = rng.choice(names, 2, replace=False)
    p_true = 1 / (1 + 10 ** ((true[y] - true[x]) / 400))
    s = float(rng.random() < p_true)                   # x가 이기면 1
    e = 1 / (1 + 10 ** ((elo[y] - elo[x]) / 400))
    elo[x] += 4 * (s - e); elo[y] -= 4 * (s - e)
print({m: round(v) for m, v in elo.items()})
```

결과가 흥미롭습니다. 진짜 실력은 A(72%)가 B(69%)보다 3%p 높게 만들었는데, 실제 500문항 점수는 **A 0.690, B 0.694로 오히려 B가 높게** 나왔습니다. 차이의 95% 신뢰구간은 [−0.064, 0.056]으로 0을 넉넉히 포함합니다. 즉 이 시험으로는 두 모델을 구별할 수 없습니다. 정답률 70% 근처에서 문항 500개의 표준오차는 약 2%p이므로, **수백 문항짜리 벤치마크의 1–3점 차이는 순위를 바꿀 근거가 못 됩니다.**

Elo는 6,000번의 쌍대 비교 뒤 A 1071, B 982, C 947로 실제 순서를 되찾습니다. 다만 절대값은 실제(1100, 1000, 950)보다 좁게 모여 있는데, 갱신 폭(K=4)이 작고 경기 순서에 따라 값이 흔들리기 때문입니다. 실제 리더보드는 모든 비교를 한꺼번에 최대우도로 맞추는 **Bradley-Terry 모델**과 부트스트랩 신뢰구간을 함께 보고합니다.

??? expert "전문가 노트 — 통계적 엄밀성, LLM 심판 편향, 자체 평가 세트 만들기"
    **오차 막대.** 문항이 독립이라 가정하면 정답률 p의 표준오차는 √(p(1−p)/n)입니다. 두 모델을 **같은 문항**으로 비교할 때는 문항별 차이(쌍대 차이)의 분산을 쓰면 신뢰구간이 크게 좁아집니다. 한 문서에서 여러 문항이 나오는 경우처럼 문항이 묶여 있으면 군집 표준오차를 써야 합니다. 생성 샘플링의 무작위성도 있으므로 여러 번 돌려 평균하거나 온도 0으로 고정하고 그 사실을 보고합니다.

    **LLM 심판의 편향.** 알려진 편향은 위치 편향(먼저 나온 답 선호), 길이 편향(긴 답 선호), 자기 선호(자기 계열 모델 답 선호), 서식 편향(목록·굵은 글씨)입니다. 대책은 두 순서로 모두 채점해 평균, 길이 통제(길이를 회귀 변수로 보정한 승률), 구체적 기준표와 정답 참고 제공, 사람 평가와의 일치도(예: 코헨 κ) 측정입니다.

    **오염 점검.** 학습 데이터와 테스트 문항의 n-그램 겹침 검사, 문항을 살짝 바꾼 변형판에서 점수 급락 여부, 공개 시점 이후 수집한 새 문항(LiveBench, LiveCodeBench) 등이 쓰입니다. 비공개로 유지하는 테스트 세트가 가장 확실합니다.

    **자체 평가 세트.** 실제 사용자 질문에서 대표적인 것과 까다로운 것을 100–500개 모으고, 정답 또는 채점 기준을 붙이고, 실패 사례가 나올 때마다 추가합니다. 프롬프트나 모델을 바꿀 때마다 이 세트를 돌리는 것이 소프트웨어의 회귀 테스트와 같은 역할을 합니다. 정확도뿐 아니라 지연 시간, 비용, 거절률, 안전 위반률도 함께 기록합니다.
