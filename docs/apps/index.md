# LLM 응용

이 섹션은 LLM을 실제 제품과 업무에 쓰는 방법을 다룹니다. 모델이 모르는 사내 문서나 최신 정보로 답하게 하는 RAG, 도구를 쓰며 여러 단계를 스스로 진행하는 에이전트, 이미지·음성까지 다루는 멀티모달, 가장 빠르게 퍼진 응용인 코딩 어시스턴트, 그리고 이 모든 것의 품질을 재는 평가 방법입니다.

| 페이지 | 핵심 질문 |
|---|---|
| [RAG (검색 증강 생성)](rag.md) | 모델이 모르는 문서로 정확하게 답하게 하려면 무엇을 어떻게 검색해 넣나? |
| [에이전트와 도구 사용](agents.md) | LLM이 도구를 부르고 여러 단계를 스스로 진행하는 구조는? 무엇이 위험한가? |
| [멀티모달 (비전·음성)](multimodal.md) | 이미지·음성·영상을 이해하고 만드는 모델은 어떻게 텍스트와 연결되나? |
| [코딩 어시스턴트](coding.md) | 자동 완성에서 저장소 전체를 고치는 에이전트까지, 코딩 AI는 어떻게 동작하고 어떻게 평가하나? |
| [평가와 벤치마크](evaluation.md) | 답이 하나가 아닌 LLM의 품질은 어떻게 재고, 벤치마크 점수는 얼마나 믿을 수 있나? |

!!! basic "응용 설계의 출발점"
    LLM 응용을 만들 때는 **가장 단순한 방법부터** 시도하고, 부족할 때만 복잡도를 올립니다.

    1. **좋은 프롬프트 + 좋은 모델** — 생각보다 많은 문제가 여기서 풀립니다.
    2. **필요한 자료를 문맥에 넣기 (RAG)** — 모델이 모르는 정보가 문제일 때.
    3. **도구 연결 (함수 호출)** — 계산, 조회, 실행이 필요할 때.
    4. **정해진 단계의 워크플로** — 여러 호출을 코드로 엮어 각 단계를 통제.
    5. **자율 에이전트** — 단계를 미리 정할 수 없을 때만. 가장 유연하지만 비용·지연·위험도 가장 큽니다.

    그리고 처음부터 **평가 세트**를 만들어 두어야 각 단계가 실제로 나아졌는지 알 수 있습니다.
