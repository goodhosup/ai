# 임베딩과 표현 학습

!!! spec "핵심 논문 · 연도"
    Bengio 외, "A Neural Probabilistic Language Model" (2003) · Mikolov 외, "word2vec" (2013) · Pennington 외, "GloVe" (2014) · Peters 외, "ELMo" (2018, 문맥 임베딩) · Reimers·Gurevych, "Sentence-BERT" (2019) · Radford 외, "CLIP" (2021) · Kusupati 외, "Matryoshka Representation Learning" (2022)

!!! basic "한눈에 보기"
    컴퓨터는 글자를 그대로 이해하지 못합니다. **임베딩**은 단어·문장·이미지를 **숫자 벡터(좌표)**로 바꾸되, **뜻이 비슷하면 가까운 곳에** 놓는 방법입니다.

    지도에서 서울과 인천은 가깝고 서울과 부산은 멉니다. 임베딩 공간에서는 "강아지"와 "개"가 가깝고, "강아지"와 "냉장고"는 멉니다. 수백–수천 차원짜리 "의미의 지도"입니다.

    - 좌표 사이 **거리나 방향**이 뜻을 담습니다. 유명한 예: 왕 − 남자 + 여자 ≈ 여왕.
    - 임베딩이 있으면 "비슷한 문서 찾기"(검색), "비슷한 상품 추천", "문의 유형 자동 분류"가 벡터 계산으로 바뀝니다.
    - LLM 안에서도 모든 토큰은 맨 처음 임베딩 벡터로 바뀐 뒤 층을 지나며 점점 풍부한 의미를 담게 됩니다.

## 원-핫에서 밀집 벡터로 { .l2 }

| 방식 | 표현 | 문제 |
|---|---|---|
| 원-핫 | 어휘 5만 개면 5만 차원 중 한 칸만 1 | 모든 단어가 서로 같은 거리 (의미 없음), 너무 큼 |
| 밀집 임베딩 | 256–4096차원 실수 벡터 | 비슷한 단어가 가까움, 작음 |

임베딩 층은 사실 (어휘 수 × d) 크기의 **조회 표**입니다. 토큰 ID로 행 하나를 꺼내는 것이고, 원-핫 벡터에 행렬을 곱하는 것과 같습니다. 이 표의 값도 학습됩니다.

## 단어 임베딩: word2vec { .l2 }

"단어의 뜻은 주변 단어가 정한다"(분포 가설). word2vec은 문장에서 주변 단어로 가운데 단어를 맞히거나(CBOW) 가운데 단어로 주변을 맞히는(skip-gram) 아주 얕은 신경망을 학습하고, 그 가중치를 임베딩으로 씁니다. 한계는 **단어마다 벡터가 하나**라는 점입니다. "배(먹는 배)"와 "배(타는 배)"가 같은 벡터입니다.

## 문맥 임베딩 { .l2 }

트랜스포머는 같은 단어라도 **문맥에 따라 다른 벡터**를 만듭니다. "배를 깎아 먹었다"의 "배"와 "배를 타고 갔다"의 "배"는 층을 지나며 서로 다른 곳으로 이동합니다. 이것이 BERT·GPT 이후 성능이 크게 오른 핵심 이유입니다.

## 문장·문서 임베딩 { .l2 }

검색과 RAG에는 문장 전체를 벡터 하나로 만드는 **임베딩 모델**을 씁니다.

| 항목 | 설명 |
|---|---|
| 학습 방법 | 대조 학습: (질문, 맞는 문서) 쌍은 가깝게, 다른 문서는 멀게 |
| 풀링 | 토큰 벡터들의 평균, 또는 특수 토큰([CLS]·마지막 토큰)의 벡터 |
| 거리 | 정규화 후 코사인 유사도 (= 내적) |
| 차원 | 384–4096. 마트료시카 학습 모델은 앞 일부만 잘라 써도 됨 |
| 평가 | MTEB 같은 검색·분류·군집 벤치마크 |

## 멀티모달 임베딩 { .l2 }

CLIP은 이미지와 그 설명문을 **같은 공간**에 놓도록 학습했습니다. 그래서 "해변의 강아지"라는 글로 사진을 검색하거나, 처음 보는 분류(제로샷)를 할 수 있습니다. 이미지 생성 모델이 글을 이해하는 것도 이런 공유 임베딩 덕분입니다 → [멀티모달](../apps/multimodal.md).

## 코드로 보기 { .l2 }

작은 단어 벡터 표를 만들어 코사인 유사도로 가장 가까운 단어를 찾고, PyTorch 임베딩 층이 조회 표라는 것을 확인합니다. (실제 서비스에서는 사전 학습된 임베딩 모델을 씁니다 → [RAG](../apps/rag.md))

```python
import numpy as np
import torch
import torch.nn as nn

# 설명용 3차원 "의미 축": [동물성, 크기, 사람과 친함]
vocab = {"강아지": [0.9, 0.2, 0.9], "개": [0.9, 0.4, 0.9], "고양이": [0.9, 0.2, 0.7],
         "늑대": [0.9, 0.5, 0.1], "냉장고": [0.0, 0.7, 0.3], "자동차": [0.0, 0.8, 0.4]}
words = list(vocab); E = np.array([vocab[w] for w in words])
E = E / np.linalg.norm(E, axis=1, keepdims=True)          # 정규화 → 내적 = 코사인

def nearest(w, k=3):
    sims = E @ E[words.index(w)]
    order = np.argsort(-sims)[1:k + 1]
    return [(words[i], round(float(sims[i]), 3)) for i in order]
print("강아지와 가까운 단어:", nearest("강아지"))

# 임베딩 층 = 조회 표
emb = nn.Embedding(num_embeddings=6, embedding_dim=3)
ids = torch.tensor([0, 3, 3])
onehot = nn.functional.one_hot(ids, 6).float()
print(torch.allclose(emb(ids), onehot @ emb.weight))      # 같은 결과
```

??? expert "전문가 노트 — 임베딩 공간의 기하, 출력 임베딩 공유, 이방성"
    **선형 구조.** word2vec의 "왕 − 남자 + 여자 ≈ 여왕"은 skip-gram + 네거티브 샘플링이 단어 공기(co-occurrence)의 점별 상호 정보량(PMI) 행렬을 암묵적으로 분해하는 것과 같다는 분석(Levy·Goldberg 2014)으로 설명됩니다. LLM 내부에서도 성별·시제·진위 같은 개념이 거의 선형 방향으로 표현된다는 "선형 표현 가설"이 활발히 연구되고, 이 방향을 더하거나 빼서 모델 행동을 조종하는 기법(activation steering)으로 이어졌습니다.

    **입력·출력 임베딩 공유.** 언어 모델의 마지막 출력 층(d × 어휘 수)은 입력 임베딩 표의 전치와 같은 모양이라 같은 가중치를 공유(weight tying)하기도 합니다. 파라미터가 줄고 작은 모델에서 성능이 좋아집니다. 어휘가 크고(15만 이상) 모델이 작으면 임베딩이 전체 파라미터의 큰 비중을 차지합니다.

    **이방성.** 사전 학습된 트랜스포머의 문맥 임베딩은 좁은 원뿔 안에 몰려 있어 아무 문장끼리도 코사인 유사도가 높게 나오는 경향이 있습니다(Ethayarajh 2019). 그래서 LLM 은닉 상태를 그대로 문장 임베딩으로 쓰면 검색 성능이 나쁘고, 대조 학습으로 따로 미세 조정한 임베딩 모델이 필요합니다.

    **양자화와 차원.** 대규모 벡터 검색에서는 임베딩을 INT8이나 1비트(이진)로 양자화하고, 후보를 빠르게 고른 뒤 원래 정밀도로 재순위하는 방식으로 메모리를 수십 배 줄입니다.
