# 논문과 모델 카드 읽는 법

!!! spec "핵심 논문 · 연도"
    Keshav, "How to Read a Paper" (2007, 3단계 읽기) · Mitchell 외, "Model Cards for Model Reporting" (2019) · Gebru 외, "Datasheets for Datasets" (2018/2021)

!!! basic "한눈에 보기"
    AI 분야의 최신 지식은 교과서보다 **논문**과 **모델 카드**에 먼저 나옵니다.

    1. **논문은 처음부터 끝까지 읽지 않습니다.** 제목·초록·그림·결론을 먼저 보고, 필요할 때만 본문으로 들어갑니다.
    2. 대부분의 AI 논문은 학회 심사 전에 **arXiv**(아카이브)에 무료로 올라옵니다. 심사를 거치지 않은 글도 많으니 주장을 그대로 믿지 않습니다.
    3. **모델 카드**는 모델의 "제품 설명서"입니다. 크기, 학습 데이터, 벤치마크 점수, 한계와 라이선스가 적혀 있습니다.

## 논문의 구조 { .l2 }

| 절 | 담긴 것 | 처음 읽을 때 |
|---|---|---|
| 제목·초록 (Abstract) | 문제, 방법, 결과를 한 문단으로 | 반드시 읽음 |
| 그림 1 | 방법 전체를 한 장으로 요약한 그림인 경우가 많음 | 반드시 봄 |
| 서론 (Introduction) | 왜 이 문제가 중요한지, 기여 목록 | 마지막 문단의 "Our contributions"만 |
| 관련 연구 (Related Work) | 기존 방법과 차이 | 건너뜀 |
| 방법 (Method) | 모델 구조, 수식, 알고리즘 | 두 번째 읽기에서 |
| 실험 (Experiments) | 데이터셋, 비교 대상, 표 | 핵심 표 하나 |
| 소거 실험 (Ablation) | 구성 요소를 하나씩 빼 봤을 때 성능 | 어떤 부분이 진짜 중요한지 보여 줌 |
| 한계·결론 | 저자가 인정하는 약점 | 반드시 읽음 |
| 부록 (Appendix) | 하이퍼파라미터, 추가 실험 | 재현할 때 |

## 3단계 읽기 { .l2 }

1. **훑기 (5–10분)**: 제목, 초록, 그림과 표, 결론. "이 논문은 무엇을 주장하나? 나에게 필요한가?"에 답합니다.
2. **이해 (1시간)**: 방법과 핵심 실험을 읽고, 그림을 직접 다시 그려 봅니다. 모르는 용어와 인용 논문을 적어 둡니다.
3. **재구성 (수 시간)**: 수식을 직접 유도하고, 가능하면 코드를 돌려 봅니다. "내가 저자라면 어떻게 했을까?"를 생각합니다.

## 실험 결과를 의심하는 체크리스트 { .l2 }

| 질문 | 이유 |
|---|---|
| 비교 대상(baseline)이 공정한가? | 비교 모델을 제대로 튜닝하지 않으면 새 방법이 좋아 보임 |
| 같은 계산량·데이터 양으로 비교했나? | 더 큰 모델·더 많은 데이터면 좋아지는 게 당연 |
| 여러 번 돌린 평균과 편차가 있나? | 시드에 따라 1–2%p 차이는 흔함 |
| 테스트셋이 학습 데이터에 섞였을 가능성은? | 인터넷 규모 학습에서는 벤치마크 오염이 흔함 |
| 소거 실험이 있나? | 어떤 구성 요소가 효과를 냈는지 확인 |
| 코드와 가중치가 공개됐나? | 재현 가능성 |

## 모델 카드 읽기 { .l2 }

| 항목 | 확인할 것 |
|---|---|
| 파라미터 수 | 총 파라미터와 **활성 파라미터**(MoE면 토큰마다 실제로 쓰는 양)를 구분 |
| 문맥 길이 | 한 번에 넣을 수 있는 최대 토큰 수 |
| 학습 데이터 | 토큰 수, 언어 비율, 데이터 기준 시점(knowledge cutoff) |
| 벤치마크 | 어떤 설정으로 쟀는지 (few-shot 개수, 사고 사슬 허용 여부, 도구 사용 여부) |
| 정밀도·형식 | BF16, FP8, INT4 양자화 버전 여부 |
| 라이선스 | 상업적 이용, 파생 모델 공개 조건 |
| 한계·위험 | 저자가 밝힌 약점, 안전성 평가 |

벤치마크 점수는 **같은 설정끼리만** 비교합니다. 같은 모델이라도 프롬프트 형식, 예시 개수, 사고 사슬 허용 여부에 따라 수 %p에서 수십 %p까지 달라집니다 → [평가와 벤치마크](../apps/evaluation.md).

## 어디서 찾나 { .l2 }

| 출처 | 특징 |
|---|---|
| arXiv (cs.LG, cs.CL, cs.CV) | 거의 모든 AI 논문의 선공개 장소. 심사 전 원고 |
| 학회 (NeurIPS, ICML, ICLR, ACL, CVPR) | 동료 심사를 거친 논문. OpenReview에서 심사평도 공개되는 경우가 많음 |
| 기업 기술 보고서 | 대형 모델의 구조와 평가. 세부 사항이 생략되는 경우가 많음 |
| Hugging Face | 모델 카드, 가중치, 데이터셋 카드 |

??? expert "전문가 노트 — 수식 표기 관례와 숫자 읽는 요령"
    **표기 관례.** 굵은 소문자 \(\mathbf{x}\)는 벡터, 굵은 대문자 \(\mathbf{W}\)는 행렬, \(\theta\)는 모델 파라미터 전체, \(\mathcal{L}\)은 손실 함수, \(\mathbb{E}_{x\sim p}[\cdot]\)은 분포 p에 대한 기댓값, \(\hat{y}\)는 모델 예측값입니다. 논문마다 행벡터·열벡터 관례가 달라 \(Wx\)와 \(xW\)가 섞이니 차원을 직접 적어 가며 읽습니다.

    **계산량 단위.** 학습 계산량은 보통 FLOPs로 적습니다. 트랜스포머는 학습 토큰 D개, 파라미터 N개일 때 약 \(6ND\) FLOPs가 듭니다. 예: 7B 모델을 2조(2T) 토큰으로 학습하면 \(6 \times 7\times10^9 \times 2\times10^{12} = 8.4\times10^{22}\) FLOPs입니다. 논문의 GPU 시간과 이 값을 비교하면 하드웨어 활용률(MFU)을 어림할 수 있습니다 → [사전 학습과 스케일링 법칙](../llm/pretraining.md).

    **"SOTA" 주장.** 최고 성능(state of the art)과의 차이가 표준편차 안이면 의미가 약합니다. 벤치마크가 포화(대부분 모델이 90% 이상)되면 작은 차이는 라벨 오류 수준일 수 있습니다.

    **재현 팁.** 부록의 학습률 스케줄, 배치 크기(토큰 단위인지 샘플 단위인지), 워밍업 스텝, 가중치 감쇠, 정밀도를 먼저 맞춥니다. 재현이 안 될 때 가장 흔한 원인은 데이터 전처리와 토크나이저 차이입니다.
