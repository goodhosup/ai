# 사전 학습과 스케일링 법칙

!!! spec "핵심 논문 · 연도"
    Radford 외, "Improving Language Understanding by Generative Pre-Training" (2018, GPT) · Radford 외, GPT-2 (2019) · Brown 외, "Language Models are Few-Shot Learners" (2020, GPT-3) · Kaplan 외, "Scaling Laws for Neural Language Models" (2020) · Hoffmann 외, "Training Compute-Optimal LLMs" (2022, Chinchilla) · Wei 외, "Emergent Abilities of LLMs" (2022) · Schaeffer 외, "Are Emergent Abilities a Mirage?" (2023) · Penedo 외, "FineWeb" (2024)

!!! basic "한눈에 보기"
    **사전 학습**은 LLM에게 세상의 글을 최대한 많이 읽히는 단계입니다. 과제는 단 하나, **"다음 토큰 맞히기"**입니다. 인터넷 문서, 책, 논문, 코드 수조 토큰을 읽으며 다음 토큰을 맞히다 보면, 문법은 물론 사실 지식, 추론 패턴, 코딩 능력까지 익히게 됩니다. 다음 단어를 잘 맞히려면 세상을 이해해야 하기 때문입니다.

    **스케일링 법칙**은 이 과정의 놀라운 규칙성입니다. 모델 크기, 데이터 양, 계산량을 늘리면 손실이 **예측 가능한 곡선**을 따라 꾸준히 줄어듭니다. 그래서 수백억 원짜리 학습을 시작하기 전에 작은 실험으로 결과를 미리 내다볼 수 있고, 이것이 지난 몇 년간 모델이 계속 커진 이유입니다.

## 학습 목표 { .l2 }

\[
\mathcal{L}(\theta) = -\frac{1}{T}\sum_{t=1}^{T}\log p_\theta(x_t \mid x_1, \dots, x_{t-1})
\]

문서 하나를 넣으면 인과 마스크 덕분에 모든 위치의 다음 토큰 예측을 **한 번의 순전파로 동시에** 학습합니다. 라벨이 필요 없는 자기 지도 학습이라 데이터를 얼마든지 늘릴 수 있습니다.

## 데이터 { .l2 }

| 단계 | 하는 일 |
|---|---|
| 수집 | 웹 크롤(Common Crawl), 책, 논문, 위키, 코드 저장소, 수학 자료 |
| 추출 | HTML에서 본문만 추출 |
| 필터링 | 언어 판별, 품질 분류기(교육적 가치 등), 유해 콘텐츠·개인정보 제거 |
| 중복 제거 | 문서·문단 단위 근사 중복 제거 (MinHash 등) |
| 혼합 | 웹·코드·수학·다국어 비율 조정, 학습 후반에 고품질 데이터 비중 확대 |
| 오염 방지 | 평가 벤치마크와 겹치는 문서 제거 |

데이터 품질이 모델 크기만큼 중요하다는 것이 최근의 공통된 결론입니다. 2024–2026년의 대표적인 오픈 모델은 10조–30조 토큰 이상으로 학습됩니다.

## 스케일링 법칙 { .l2 }

손실은 파라미터 수 N, 학습 토큰 수 D에 대해 대략 다음 꼴을 따릅니다(Chinchilla).

\[
L(N, D) \approx E + \frac{A}{N^{\alpha}} + \frac{B}{D^{\beta}}
\]

E는 데이터 자체의 줄일 수 없는 엔트로피, 나머지 두 항은 모델이 작아서·데이터가 적어서 생기는 손실입니다. 학습 계산량은 \(C \approx 6ND\) FLOPs입니다.

| 연구 | 결론 | 영향 |
|---|---|---|
| Kaplan 외 (2020) | 계산이 늘면 주로 **모델을 키워라** | GPT-3 (175B, 3천억 토큰) |
| Chinchilla (2022) | 모델과 데이터를 **같은 비율로** 키워라. 최적은 파라미터당 약 **20토큰** | 70B를 1.4T 토큰으로 학습해 280B 모델(Gopher)을 능가 |
| 이후 실무 (2023–) | 추론 비용을 고려하면 작은 모델을 **훨씬 오래** 학습하는 것이 이득 | 8B 모델을 15T 토큰 (파라미터당 약 1,900토큰) |

Chinchilla 최적은 "학습 계산을 가장 효율적으로 쓰는" 기준입니다. 서비스할 때는 모델이 작을수록 추론이 싸므로, 학습에 계산을 더 쓰더라도 작은 모델을 과하게 학습시키는 것(over-training)이 전체 비용으로는 유리합니다.

## 창발 능력 논쟁 { .l2 }

GPT-3 이후 "모델이 일정 크기를 넘으면 갑자기 새 능력(산술, 다단계 추론)이 나타난다"는 **창발** 관찰이 보고됐습니다. 반론은 정확도처럼 "맞으면 1, 틀리면 0"인 지표를 쓰면 매끄러운 향상도 계단처럼 보인다는 것입니다(Schaeffer 외 2023). 손실 같은 연속 지표로 보면 대부분 매끄럽게 좋아집니다. 다만 사용자 입장에서 "어느 순간 쓸 만해지는" 경험은 실재합니다.

## 코드로 보기 { .l2 }

Chinchilla 논문의 적합 계수로 계산 예산별 최적 모델 크기와 토큰 수를 구하고, 6ND로 학습 계산량과 GPU 시간을 어림합니다.

```python
import numpy as np

E, A, B, alpha, beta = 1.69, 406.4, 410.7, 0.34, 0.28        # Hoffmann 외 (2022) 적합값
L = lambda N, D: E + A / N ** alpha + B / D ** beta

for C in (1e21, 1e23, 1e25):                                  # 학습 FLOPs 예산
    Ns = np.logspace(7, 13, 4000)
    Ds = C / (6 * Ns)                                          # C = 6ND
    i = np.argmin(L(Ns, Ds))
    print(f"C={C:.0e}: 최적 N≈{Ns[i]/1e9:7.2f}B, D≈{Ds[i]/1e9:8.0f}B 토큰, "
          f"토큰/파라미터≈{Ds[i]/Ns[i]:4.0f}, 예상 손실≈{L(Ns[i], Ds[i]):.3f}")

# 8B 모델을 15T 토큰으로 학습: 계산량과 H100 GPU 시간 어림
N, D = 8e9, 15e12
flops = 6 * N * D
h100_bf16 = 989e12                                             # 밀집 BF16 최대 성능 (FLOP/s)
mfu = 0.4                                                      # 실제 활용률 가정
gpu_hours = flops / (h100_bf16 * mfu) / 3600
print(f"8B×15T: {flops:.1e} FLOPs, H100 약 {gpu_hours/1e4:.0f}만 GPU시간 (MFU 40% 가정)")
```

이 적합식으로 구한 최적 비율은 50–120토큰/파라미터로, 원 논문의 다른 두 방법이 준 "약 20"보다 크게 나옵니다. 이 불일치는 재현 연구(Besiroglu 외 2024)에서도 지적되었고, 적합 방법에 따라 최적 비율이 수십 배 범위에서 달라질 수 있다는 점을 보여 줍니다. 계산 예산이 클수록 최적 비율이 커지는 경향도 보입니다. 8B 모델을 15T 토큰 학습하면 약 \(7\times10^{23}\) FLOPs, H100으로 약 51만 GPU시간 규모입니다.

??? expert "전문가 노트 — MFU, 학습률 스케줄과 스케일링, 데이터 고갈, 합성 데이터"
    **MFU.** 모델 FLOPs 활용률 = (6ND ÷ 학습 시간) ÷ 하드웨어 최대 FLOP/s입니다. 대형 학습에서 35–55%가 일반적이며, 통신·메모리 대역폭·파이프라인 공백이 나머지를 잡아먹습니다 → [분산 학습](../systems/distributed.md).

    **스케일링 법칙의 함정.** 적합 결과는 학습률 스케줄(코사인 길이를 학습 길이에 맞췄는지), 임베딩 파라미터 포함 여부, 데이터 품질에 민감합니다. Kaplan과 Chinchilla 결론의 차이도 상당 부분 이런 실험 설정 차이로 설명됩니다(Porian 외 2024 등). 작은 모델에서 큰 모델로 외삽할 때는 같은 레시피를 유지해야 합니다.

    **데이터 고갈.** 고품질 공개 텍스트는 수십조 토큰 규모로 추정되어, 최대 모델들은 이미 그 한계에 가까워졌습니다. 대응책은 (1) 같은 데이터를 여러 에폭 반복(4에폭까지는 손실이 거의 없다는 보고, Muennighoff 외 2023), (2) 더 큰 모델이 만든 **합성 데이터**, (3) 다국어·멀티모달 데이터 확장, (4) 강화 학습으로 계산을 데이터 대신 쓰기입니다.

    **추론 계산의 스케일링.** 2024년 이후에는 학습 계산뿐 아니라 **추론 시 계산**(더 길게 생각하기, 여러 번 시도하고 고르기)을 늘리면 성능이 예측 가능하게 오른다는 두 번째 스케일링 축이 확인되었습니다 → [추론 모델과 사고 사슬](reasoning.md).

    **중간 학습(mid-training).** 사전 학습 후반에 고품질 데이터·긴 문맥·수학·코드 비중을 높이는 별도 단계를 두는 것이 표준이 되었습니다. 학습률 감쇠 구간에 고품질 데이터를 넣는 것이 특히 효과적이라는 보고가 많습니다.
