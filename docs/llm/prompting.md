# 프롬프트 설계

!!! spec "핵심 논문 · 연도"
    Brown 외, GPT-3 (2020, 퓨샷 문맥 내 학습) · Wei 외, "Chain-of-Thought Prompting" (2022) · Kojima 외, "Large Language Models are Zero-Shot Reasoners" (2022, "단계별로 생각해 보자") · Wang 외, "Self-Consistency" (2022) · Holtzman 외, "The Curious Case of Neural Text Degeneration" (2019, nucleus 샘플링) · Liu 외, "Lost in the Middle" (2023) · Greshake 외, "Indirect Prompt Injection" (2023)

!!! basic "한눈에 보기"
    LLM은 **아주 유능하지만 우리 사정을 전혀 모르는 신입 동료**와 같습니다. "보고서 좀 정리해 줘"라고만 하면 누구를 위한, 어떤 길이의, 어떤 형식의 보고서인지 짐작으로 채웁니다. 좋은 프롬프트는 좋은 업무 지시와 같습니다.

    1. **목적과 독자**를 말합니다. "팀장님께 3분 안에 보고할 요약"
    2. **배경 자료**를 줍니다. 모델은 회사 내부 사정을 모릅니다.
    3. **원하는 형식**을 보여 줍니다. 가능하면 예시를 하나 넣습니다.
    4. **제약과 판단 기준**을 적습니다. "확실하지 않으면 모른다고 쓸 것"
    5. 복잡한 일은 **단계로 나누거나**, 답하기 전에 생각하게 합니다.

    모델이 좋아질수록 요령보다 **명확하고 구체적인 설명**이 중요해집니다.

## 프롬프트의 구성 요소 { .l2 }

| 요소 | 위치 | 예 |
|---|---|---|
| 시스템 프롬프트 | 대화 맨 앞 (개발자가 설정) | 역할, 말투, 금지 사항, 출력 규칙 |
| 맥락 자료 | 질문 앞 (긴 문서는 앞에 두고 질문은 뒤에) | 계약서 원문, 검색된 문서, 코드 |
| 지시 | 명확한 동사로 | "아래 계약서에서 해지 조건을 모두 찾아 표로 정리하라" |
| 예시 (퓨샷) | 지시 뒤 | 입력-출력 쌍 1–5개 |
| 출력 형식 | 끝부분 | JSON 스키마, 표, 글자 수 |

## 대표 기법 { .l2 }

| 기법 | 방법 | 효과 |
|---|---|---|
| 제로샷 | 지시만 | 쉬운 과제, 최신 모델은 대부분 충분 |
| 퓨샷 | 예시 몇 개 제공 | 형식·말투·판단 기준을 정확히 전달 |
| 사고 사슬 (CoT) | "단계별로 추론한 뒤 답하라" 또는 풀이 예시 | 수학·논리 과제 정확도 향상 (추론 모델은 기본 내장) |
| 자기 일관성 | 여러 번 생성해 다수결 | 정답이 하나인 과제의 정확도 향상 |
| 역할 부여 | "당신은 10년 차 세무사다" | 어휘·관점 조정 (효과는 과제마다 다름) |
| 구조화 출력 | JSON 스키마 지정, API의 구조화 출력 기능 | 프로그램이 파싱 가능한 결과 |
| 프롬프트 체이닝 | 큰 일을 여러 호출로 나눔 | 각 단계 품질 관리, 디버깅 쉬움 |
| XML·마크다운 구획 | `<문서>…</문서>`처럼 구역 표시 | 자료와 지시를 섞이지 않게 구분 |

## 샘플링 설정 { .l2 }

모델은 다음 토큰마다 확률 분포를 내고, 그중 하나를 **뽑습니다**. 어떻게 뽑느냐가 답의 성격을 바꿉니다.

| 설정 | 뜻 | 낮게 / 높게 |
|---|---|---|
| temperature | softmax 온도 | 0 근처: 결정적·일관 / 1 이상: 다양·창의적 (오류 증가) |
| top-p (nucleus) | 누적 확률 p까지의 후보만 사용 | 0.9 정도가 흔함 |
| top-k | 상위 k개 후보만 사용 | 작을수록 보수적 |
| max tokens | 생성 길이 상한 | 너무 작으면 답이 잘림 |
| stop sequence | 이 문자열이 나오면 중단 | 형식 제어 |

사실 확인·코드·추출은 낮은 온도, 브레인스토밍·창작은 높은 온도가 맞습니다. (추론 모델 중에는 온도 설정을 고정한 것도 있습니다.)

## 코드로 보기 { .l2 }

같은 로짓에서 온도·top-p에 따라 어떤 토큰이 뽑히는지 시뮬레이션합니다.

```python
import numpy as np

vocab = ["맑음", "흐림", "비", "눈", "태풍", "외계인"]
logits = np.array([3.0, 2.2, 1.5, 0.3, -0.5, -3.0])

def sample(logits, temperature=1.0, top_p=1.0, n=10000, seed=0):
    z = logits / max(temperature, 1e-6)
    p = np.exp(z - z.max()); p /= p.sum()
    order = np.argsort(-p); cum = np.cumsum(p[order])
    keep = order[: np.searchsorted(cum, top_p) + 1]       # 누적 확률 top_p까지
    q = np.zeros_like(p); q[keep] = p[keep]; q /= q.sum()
    draws = np.random.default_rng(seed).choice(len(p), size=n, p=q)
    return {vocab[i]: round(float(c) / n, 3) for i, c in zip(*np.unique(draws, return_counts=True))}

print("T=0.2        :", sample(logits, 0.2))
print("T=1.0        :", sample(logits, 1.0))
print("T=1.5        :", sample(logits, 1.5))
print("T=1.5, p=0.9 :", sample(logits, 1.5, top_p=0.9))
```

온도 0.2에서는 거의 항상 "맑음"이고, 1.5에서는 "외계인"처럼 엉뚱한 후보도 가끔 뽑힙니다. top-p 0.9를 함께 쓰면 꼬리의 엉뚱한 후보가 잘려 나갑니다.

??? expert "전문가 노트 — 문맥 내 학습의 정체, 위치 편향, 프롬프트 인젝션"
    **문맥 내 학습.** 퓨샷 예시로 성능이 오르는 이유에 대해, 모델이 예시에서 새 과제를 "학습"한다기보다 이미 아는 과제를 **찾아내고 형식을 맞추는** 역할이 크다는 분석이 있습니다(Min 외 2022: 예시의 라벨을 무작위로 바꿔도 성능 하락이 작음). 반면 큰 모델일수록 예시의 라벨을 실제로 따르는 정도가 커지며, 트랜스포머가 문맥 안에서 경사하강법과 비슷한 계산을 한다는 이론적 결과도 있습니다.

    **위치 편향.** 긴 문맥에서 정보가 처음이나 끝에 있을 때보다 **가운데**에 있을 때 활용도가 떨어지는 "중간에서 길을 잃음" 현상이 보고됐습니다(Liu 외 2023). 최신 모델은 크게 개선됐지만, 핵심 지시는 긴 자료 **뒤에** 다시 적는 것이 여전히 안전합니다.

    **프롬프트 캐싱.** 시스템 프롬프트·긴 문서처럼 반복되는 앞부분은 서버가 KV 캐시를 재사용해 비용과 지연을 크게 줄일 수 있습니다. 그러려면 **바뀌지 않는 부분을 앞에, 바뀌는 부분을 뒤에** 두어야 합니다 → [추론 최적화](../systems/inference.md).

    **프롬프트 인젝션.** 모델은 지시와 데이터를 근본적으로 구분하지 못합니다. 웹 페이지·이메일·문서 안에 "이전 지시를 무시하고…" 같은 문장이 숨어 있으면 모델이 따를 수 있습니다(간접 인젝션). 에이전트가 도구를 쓰고 외부 데이터를 읽을수록 위험이 커지며, 권한 최소화, 신뢰 경계 표시, 위험 행동 전 사람 확인이 기본 방어입니다 → [에이전트와 도구 사용](../apps/agents.md).
