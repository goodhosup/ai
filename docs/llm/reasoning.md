# 추론 모델과 사고 사슬

!!! spec "핵심 논문 · 연도"
    Wei 외, "Chain-of-Thought Prompting Elicits Reasoning" (2022) · Wang 외, "Self-Consistency" (2022) · Lightman 외, "Let's Verify Step by Step" (2023, 과정 보상) · OpenAI, "Learning to Reason with LLMs" (2024, o1) · Snell 외, "Scaling LLM Test-Time Compute Optimally" (2024) · DeepSeek-AI, "DeepSeek-R1" (2025) · Muennighoff 외, "s1: Simple test-time scaling" (2025)

!!! basic "한눈에 보기"
    어려운 수학 문제를 받으면 사람은 바로 답을 말하지 않고 **연습장에 풀이를 적습니다**. 중간에 틀리면 지우고 다른 방법을 시도합니다. 초기 LLM은 이 연습장 없이 곧바로 답을 말해야 했습니다.

    **사고 사슬(Chain of Thought)**은 LLM에게 답하기 전에 풀이 과정을 글로 쓰게 하는 것입니다. 그것만으로 수학·논리 문제의 정답률이 크게 올랐습니다.

    **추론 모델**(2024년 이후 등장)은 한 걸음 더 나가, 강화 학습으로 **스스로 길게 생각하는 습관**을 학습한 모델입니다. 답하기 전에 수천–수만 토큰의 내부 풀이를 쓰며 계획하고, 검산하고, 막히면 되돌아갑니다. 그 결과 수학 경시대회, 프로그래밍 대회, 과학 문제에서 성능이 크게 뛰었습니다.

    대가는 **시간과 비용**입니다. 생각을 오래 할수록 정확해지지만 느리고 비싸집니다.

## 생각을 길게 하면 왜 좋아지나 { .l2 }

| 이유 | 설명 |
|---|---|
| 계산 공간 | 트랜스포머는 토큰 하나를 만들 때 고정된 양의 계산만 합니다. 중간 토큰을 쓰면 그만큼 계산 단계가 늘어납니다 |
| 문제 분해 | 큰 문제를 작은 단계로 나누면 각 단계는 모델이 이미 잘하는 수준이 됩니다 |
| 오류 수정 | 풀이를 보며 틀린 부분을 발견하고 고칠 기회가 생깁니다 |
| 탐색 | 여러 접근을 시도해 보고 맞는 것을 고릅니다 |

## 추론 시 계산을 늘리는 방법 { .l2 }

| 방법 | 설명 | 필요 조건 |
|---|---|---|
| 사고 사슬 프롬프트 | "단계별로 풀어라" | 없음 |
| 자기 일관성 (다수결) | 여러 번 풀어 가장 많이 나온 답 선택 | 답이 비교 가능해야 함 |
| 최선-of-N | 여러 답 중 검증기·보상 모델이 가장 높게 매긴 답 선택 | 좋은 검증기 |
| 트리 탐색 | 중간 단계마다 여러 갈래를 펼치고 유망한 쪽을 탐색 | 단계별 평가기 |
| **긴 사고 (추론 모델)** | 모델이 한 번의 생성 안에서 탐색·검산·되돌아가기를 수행 | 강화 학습으로 학습된 모델 |

## 추론 모델은 어떻게 학습하나 { .l2 }

```mermaid
flowchart LR
    A["기반 모델"] --> B["(선택) 소량의 긴 풀이 예시로 SFT<br/>콜드 스타트"]
    B --> C["대규모 강화 학습<br/>수학 정답·코드 테스트 등<br/>검증 가능한 보상"]
    C --> D["거절 샘플링으로 좋은 풀이 수집<br/>→ SFT로 다듬기"]
    D --> E["일반 선호 학습<br/>도움·안전"]
    E --> F["추론 모델"]
```

DeepSeek-R1(2025)은 기반 모델에 **정답 여부만 보상으로** 주는 강화 학습을 했더니, 따로 가르치지 않았는데도 풀이가 점점 길어지고 "잠깐, 다시 확인해 보자" 같은 **자기 검증·되돌아가기 행동이 저절로** 나타났다고 보고했습니다. 추론 모델의 긴 사고를 작은 모델에 SFT로 옮기는 **증류**도 매우 효과적이었습니다.

## 언제 추론 모델을 쓰나 { .l2 }

| 잘 맞음 | 굳이 필요 없음 |
|---|---|
| 수학·과학 문제, 복잡한 코딩, 버그 추적 | 간단한 질의응답, 번역, 요약 |
| 여러 조건을 동시에 만족해야 하는 계획·일정 | 빠른 응답이 중요한 대화·자동 완성 |
| 긴 문서에서 미묘한 논리 판단 | 정형화된 추출 |
| 에이전트의 다단계 작업 | 대량·저비용 처리 |

많은 서비스가 "생각 예산(thinking budget)"이나 추론 강도 설정을 제공해, 과제 난이도에 맞게 조절할 수 있습니다(2026년 11월 기준).

## 코드로 보기 { .l2 }

한 번 풀 때 정답 확률이 p인 모델로 n번 풀어 다수결(자기 일관성)을 하거나, 완벽한 검증기로 하나라도 맞으면 성공(pass@n)으로 보면 정확도가 어떻게 오르는지 계산합니다. 오답은 여러 가지로 흩어진다고 가정합니다.

```python
import numpy as np

rng = np.random.default_rng(0)

def simulate(p_correct, n, trials=20000, n_wrong_answers=5):
    maj = passn = 0
    for _ in range(trials):
        correct = rng.random(n) < p_correct
        answers = np.where(correct, 0, rng.integers(1, n_wrong_answers + 1, n))   # 0이 정답
        vals, counts = np.unique(answers, return_counts=True)
        maj += vals[np.argmax(counts)] == 0            # 다수결 (동률이면 작은 값 = 정답 우선)
        passn += correct.any()                         # 완벽한 검증기가 있다면
    return maj / trials, passn / trials

for n in (1, 5, 15, 45):
    m, pk = simulate(0.4, n)
    print(f"n={n:2d}: 다수결 정확도={m:.3f}  pass@n={pk:.3f}")
```

한 번에 40%만 맞히는 모델도 오답이 흩어져 있으면 다수결로 정확도가 크게 오르고, 좋은 검증기가 있으면 더 오릅니다. 다만 **오답이 한 가지로 몰리는** 문제(그럴듯한 함정)에서는 다수결이 오히려 오답을 고릅니다. `n_wrong_answers=1`로 바꿔 확인해 보세요.

??? expert "전문가 노트 — 추론 시 스케일링, 과정 보상, 사고의 충실성"
    **추론 시 계산 최적 배분.** Snell 외(2024)는 같은 추론 계산 예산이라면 쉬운 문제에는 순차적 수정(긴 사고)이, 어려운 문제에는 병렬 탐색과 검증기의 조합이 유리하며, 난이도에 맞게 배분하면 파라미터가 14배 큰 모델과 맞먹을 수 있다고 보고했습니다. s1(2025)은 1,000개의 풀이 예시로 SFT한 뒤, 생성이 끝나려 할 때 "Wait"를 붙여 사고를 강제로 늘리는 것만으로 성능이 예산에 따라 오르는 것을 보였습니다.

    **결과 보상과 과정 보상.** 최종 답만 채점하는 결과 보상(ORM)은 운 좋게 맞은 엉터리 풀이도 보상합니다. 단계마다 채점하는 과정 보상 모델(PRM, Lightman 외 2023)은 더 정밀하지만 단계별 라벨이 비쌉니다. 대규모 RLVR에서는 결과 보상만으로도 충분히 잘 된다는 것이 2025년 이후의 경험적 결론에 가깝고, PRM은 탐색·재순위에 주로 쓰입니다.

    **사고의 충실성.** 모델이 보여 주는 사고 과정이 실제 계산 과정을 정직하게 반영하는지는 별개의 문제입니다. 힌트를 받아 답을 바꾸고도 사고 과정에서는 힌트를 언급하지 않는 사례가 보고되었습니다(Anthropic 2025, Chen 외 "Reasoning Models Don't Always Say What They Think"). 사고 과정 감시(CoT monitoring)는 유용한 안전 도구지만, 사고 과정에 직접 최적화 압력을 가하면 감시를 피하는 쪽으로 학습될 위험도 지적됩니다 → [정렬과 AI 안전](../society/safety.md).

    **과잉 사고.** 추론 모델은 쉬운 문제에도 불필요하게 길게 생각하거나, 정답에 도달한 뒤에도 계속 검산하는 경향이 있습니다. 길이 벌점, 난이도 적응형 예산, 사고 압축이 연구되고 있습니다.
