# 벡터·행렬·텐서

!!! spec "핵심 논문 · 연도"
    Strang, *Introduction to Linear Algebra* (교과서) · Golub·Van Loan, *Matrix Computations* · Eckart·Young (1936, 저랭크 근사) · Mikolov 외, "Efficient Estimation of Word Representations in Vector Space" (2013, 단어 벡터 연산)

!!! basic "한눈에 보기"
    - **벡터**는 숫자를 한 줄로 늘어놓은 것입니다. 사람을 (키, 몸무게, 나이)로 나타내면 3차원 벡터입니다. AI에서는 단어 하나, 이미지 하나도 수백–수천 차원 벡터로 나타냅니다.
    - **행렬**은 숫자를 표처럼 늘어놓은 것이고, 벡터를 다른 벡터로 **바꾸는 기계**로 볼 수 있습니다. 신경망의 한 층은 사실상 "행렬을 곱하고 비틀기"입니다.
    - **텐서**는 이것을 3차원, 4차원으로 늘린 것입니다. 사진 여러 장은 (장 수, 높이, 너비, 색) 4차원 텐서입니다.
    - **내적**은 두 벡터가 얼마나 같은 방향을 가리키는지 재는 숫자입니다. 검색, 추천, 어텐션이 모두 내적으로 "비슷함"을 잽니다.

## 모양(shape)으로 생각하기 { .l2 }

| 이름 | 차원 수 | 모양 예 | AI에서의 예 |
|---|---|---|---|
| 스칼라 | 0 | `()` | 손실 값, 학습률 |
| 벡터 | 1 | `(768,)` | 토큰 하나의 임베딩 |
| 행렬 | 2 | `(768, 3072)` | FFN 가중치 |
| 3차 텐서 | 3 | `(B, T, d)` | 배치 × 토큰 × 임베딩 차원 |
| 4차 텐서 | 4 | `(B, C, H, W)` | 이미지 배치 (PyTorch 관례) |

행렬 곱 \(C = AB\)는 \(A\)가 (m × k), \(B\)가 (k × n)일 때만 정의되고 결과는 (m × n)입니다. **안쪽 차원 k가 같아야** 합니다. 딥러닝 코드에서 나는 오류의 절반은 이 모양이 안 맞아서 생깁니다.

\[
C_{ij} = \sum_{l=1}^{k} A_{il} B_{lj}
\]

곱셈·덧셈 횟수는 \(m \times k \times n\)번씩, 즉 약 \(2mkn\) FLOPs입니다. 이 숫자가 모델의 계산량 어림의 출발점입니다.

## 내적과 코사인 유사도 { .l2 }

\[
\mathbf{a}\cdot\mathbf{b} = \sum_i a_i b_i = \|\mathbf{a}\|\,\|\mathbf{b}\|\cos\theta
\qquad
\cos\theta = \frac{\mathbf{a}\cdot\mathbf{b}}{\|\mathbf{a}\|\,\|\mathbf{b}\|}
\]

| 코사인 값 | 의미 |
|---|---|
| 1 | 같은 방향 (매우 비슷) |
| 0 | 직교 (관련 없음) |
| −1 | 반대 방향 |

임베딩 검색([RAG](../apps/rag.md))은 질문 벡터와 문서 벡터의 코사인 유사도가 큰 문서를 찾는 일이고, [어텐션](../arch/attention.md)은 Query와 Key의 내적으로 "누구에게 주목할지"를 정합니다.

## 행렬은 변환이다 { .l2 }

행렬 \(W\)를 벡터 \(\mathbf{x}\)에 곱하면 회전·확대·찌그러뜨리기·차원 바꾸기가 한꺼번에 일어납니다. 신경망의 한 층은

\[
\mathbf{h} = \sigma(W\mathbf{x} + \mathbf{b})
\]

입니다. \(W\mathbf{x} + \mathbf{b}\)는 직선(평면)적인 변환이고, 비선형 함수 \(\sigma\)가 그것을 구부립니다. 층을 쌓으면 복잡한 곡면도 표현할 수 있습니다 → [퍼셉트론과 MLP](../dl/mlp.md).

## 코드로 보기 { .l2 }

```python
import numpy as np

rng = np.random.default_rng(0)
B, T, d, d_ff = 2, 5, 8, 32
x = rng.normal(size=(B, T, d))          # 배치 2, 토큰 5개, 8차원
W = rng.normal(size=(d, d_ff))          # 층 가중치
h = x @ W                               # 마지막 축끼리 곱함 → (2, 5, 32)
print(h.shape)

# 코사인 유사도
a, b = np.array([1.0, 2.0, 3.0]), np.array([2.0, 4.0, 6.1])
cos = a @ b / (np.linalg.norm(a) * np.linalg.norm(b))
print(round(cos, 4))                    # 1에 가까움: 거의 같은 방향

# 행렬 곱의 FLOPs 어림: 2·m·k·n
m, k, n = 4096, 4096, 4096
print(f"{2 * m * k * n / 1e9:.1f} GFLOPs")
```

출력은 `(2, 5, 32)`, `1.0`, `137.4 GFLOPs`입니다. `@`는 앞쪽 축을 배치로 보고 마지막 두 축끼리 행렬 곱을 합니다(브로드캐스팅).

## 꼭 알아 둘 연산 { .l2 }

| 연산 | 기호 | 쓰임 |
|---|---|---|
| 전치 | \(A^\top\) | \(QK^\top\) (어텐션 점수) |
| 원소별 곱 | \(\odot\) | 게이트 (LSTM, SwiGLU), 마스크 |
| 노름 | \(\|\mathbf{x}\|_2\) | 정규화, 그래디언트 클리핑, 가중치 감쇠 |
| 역행렬 | \(A^{-1}\) | 선형 회귀의 닫힌 해 (딥러닝에서는 거의 안 씀) |
| 고윳값·고유벡터 | \(A\mathbf{v} = \lambda\mathbf{v}\) | PCA, 학습 안정성 분석 |
| 특잇값 분해 (SVD) | \(A = U\Sigma V^\top\) | 저랭크 근사, LoRA의 직관, 압축 |

??? expert "전문가 노트 — 랭크, SVD와 저랭크 근사, 수치 정밀도"
    **랭크와 저랭크 근사.** 행렬의 랭크는 독립적인 방향의 수입니다. SVD \(A = U\Sigma V^\top\)에서 큰 특잇값 r개만 남긴 \(A_r\)는 프로베니우스 노름 기준으로 가장 좋은 랭크-r 근사입니다(Eckart–Young 정리). (m × n) 행렬을 저장하는 데 \(mn\)개 대신 \(r(m+n)\)개 숫자면 됩니다. [LoRA](../llm/finetuning.md)는 미세 조정 중 가중치 변화량 \(\Delta W\)가 저랭크라고 가정하고 \(\Delta W = BA\) (B: d × r, A: r × k)만 학습합니다.

    **고차원의 직관.** 고차원에서는 무작위 벡터 두 개가 거의 항상 직교에 가깝습니다(내적의 기댓값 0, 표준편차 \(\sim 1/\sqrt{d}\)로 정규화했을 때). 그래서 수천 차원 임베딩 공간에는 서로 거의 간섭하지 않는 방향이 매우 많고, 모델이 차원 수보다 많은 "특징"을 겹쳐 담을 수 있다는 가설(superposition)이 나옵니다.

    **수치 정밀도.** 행렬 곱은 곱셈 결과를 길게 더하므로 오차가 쌓입니다. GPU 텐서 코어는 입력을 BF16·FP8로 받아도 누적은 FP32로 합니다. 작은 값이 큰 값에 더해지며 사라지는 문제 때문에 합의 순서에 따라 결과가 비트 단위로 달라질 수 있고, 이것이 같은 입력에도 GPU 결과가 미세하게 달라지는 원인 중 하나입니다 → [양자화와 경량화](../systems/quantization.md).

    **메모리 배치.** 같은 행렬도 행 우선(row-major)·열 우선 저장에 따라 접근 속도가 다릅니다. PyTorch의 `transpose`는 데이터를 옮기지 않고 보는 방식(stride)만 바꾸므로, 이후 `view`가 실패하면 `.contiguous()`가 필요합니다.
