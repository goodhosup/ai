# 머신러닝

이 섹션은 딥러닝 이전부터 쓰여 온 머신러닝의 기본기를 다룹니다. "데이터에서 배운다"는 것이 구체적으로 무엇인지, 과적합은 왜 생기고 어떻게 막는지, 모델을 어떻게 공정하게 평가하는지는 LLM 시대에도 그대로 통하는 원리입니다. 표 형식 데이터에서는 지금도 이 섹션의 방법(특히 그래디언트 부스팅)이 딥러닝보다 나은 경우가 많습니다.

| 페이지 | 핵심 질문 |
|---|---|
| [지도·비지도·강화 학습](paradigms.md) | 정답이 있을 때, 없을 때, 보상만 있을 때 각각 어떻게 배우나? |
| [선형 회귀와 로지스틱 회귀](linear-models.md) | 가장 단순한 모델은 무엇을 하고, 신경망과 어떻게 이어지나? |
| [결정 트리와 앙상블](trees.md) | 스무고개 같은 트리를 여러 개 묶으면 왜 강해지나? |
| [SVM과 커널](svm.md) | 마진을 최대화한다는 것은 무엇이고, 커널 트릭은 어떻게 곡선 경계를 만드나? |
| [군집과 차원 축소](unsupervised.md) | 정답 없이 데이터의 구조를 어떻게 찾고, 고차원 데이터를 어떻게 눈으로 보나? |
| [과적합과 정규화](overfitting.md) | 학습 데이터만 외운 모델은 어떻게 알아보고, 어떻게 막나? |

!!! basic "머신러닝 프로젝트의 흐름"
    모델 종류보다 이 흐름을 지키는 것이 더 중요합니다.

    1. **문제 정의** — 무엇을 예측하나? 성공을 어떤 숫자로 재나?
    2. **데이터 수집·정제** — 결측치, 이상치, 라벨 오류. 실무 시간의 대부분이 여기에 듭니다.
    3. **데이터 분할** — 학습·검증·테스트로 나누고, 테스트셋은 마지막까지 보지 않습니다.
    4. **기준선(baseline)** — 가장 단순한 모델(평균값 예측, 로지스틱 회귀)부터 만듭니다.
    5. **개선** — 특징, 모델, 하이퍼파라미터를 검증셋으로 비교합니다.
    6. **최종 평가와 배포** — 테스트셋으로 한 번만 평가하고, 배포 후에도 성능을 계속 감시합니다.
