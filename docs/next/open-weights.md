# 오픈 웨이트 모델

!!! spec "핵심 사건 · 연도"
    Radford 외, "GPT-2 단계적 공개" (2019) · BigScience, "BLOOM" (2022) · Touvron 외, "LLaMA" (2023) · Mistral, "Mistral 7B / Mixtral" (2023) · Meta, "Llama 3" (2024) · DeepSeek-AI, "DeepSeek-V3 / R1" (2024·2025) · OSI, "오픈소스 AI 정의 1.0" (2024) · OpenAI, "gpt-oss" (2025) · AI2, "OLMo 2 / OLMo 3" (2025)

!!! basic "한눈에 보기"
    **오픈 웨이트 모델**은 학습된 가중치 파일을 누구나 내려받아 자기 컴퓨터나 서버에서 실행하고, 고치고, 추가 학습할 수 있게 공개한 모델입니다. 반대로 **폐쇄형 모델**은 회사의 API로만 쓸 수 있습니다.

    요리에 비유하면 폐쇄형은 식당에서 사 먹는 요리, 오픈 웨이트는 **완성된 요리를 통째로 포장해 주는 것**입니다. 집에서 데워 먹고, 양념을 더할 수도 있습니다. 다만 레시피(학습 코드)와 재료 목록(학습 데이터)까지 공개해야 진정한 **오픈소스**라고 부를 수 있다는 주장이 있고, 그런 모델은 아직 소수입니다.

    오픈 웨이트가 중요한 이유는 다음과 같습니다.

    - **통제와 개인정보**: 데이터를 밖으로 보내지 않고 사내·기기 안에서 실행 (→ [로컬 LLM 실행](../practice/local-llm.md))
    - **맞춤화**: 내 데이터로 미세 조정, 양자화, 증류
    - **비용**: 대량 처리에서 API보다 저렴할 수 있음
    - **연구와 투명성**: 내부를 들여다보고 실험할 수 있음

## 공개의 스펙트럼 { .l2 }

| 수준 | 공개 범위 | 예 |
|---|---|---|
| API 전용 | 없음 (사용만 가능) | 대부분의 최상위 상용 모델 |
| 오픈 웨이트, 제한 라이선스 | 가중치 + 사용 조건(사용자 수 상한, 용도 제한, 표기 의무) | Llama 계열(커뮤니티 라이선스), 일부 Qwen·Kimi·Gemma 버전 |
| 오픈 웨이트, 허용 라이선스 | 가중치 + Apache 2.0 / MIT 등 | DeepSeek(MIT), 다수 Qwen(Apache 2.0), gpt-oss(Apache 2.0), Mistral 일부 |
| 완전 공개 | 가중치 + 학습 코드 + 학습 데이터(또는 재현 방법) + 중간 체크포인트 | AI2 OLMo, Pythia, LLM360 등 |

OSI(오픈소스 이니셔티브)는 2024년 「오픈소스 AI 정의」에서 가중치·코드와 함께 **데이터에 대한 충분히 상세한 정보**를 요구했습니다. 그래서 많은 모델은 "오픈소스"보다 "**오픈 웨이트**"라고 부르는 것이 정확합니다.

2025년 이후 성능 상위의 오픈 웨이트 모델은 **중국 연구소**가 다수를 차지하게 되었습니다. 최전선 폐쇄형 모델과의 격차는 벤치마크 기준으로 대략 수개월~1년 수준으로 평가되지만, 긴 에이전트 작업과 신뢰성에서는 격차가 더 크다는 평가도 있습니다.

## 코드로 보기 { .l2 }

오픈 웨이트 최상위 모델은 대부분 [MoE](../llm/moe.md)입니다. MoE는 **메모리는 총 파라미터만큼, 연산은 활성 파라미터만큼** 필요하다는 점이 직접 운영할 때 가장 중요한 특성입니다.

```python
models = {   # (총 파라미터, 토큰당 활성 파라미터), 단위: 십억
    "gpt-oss-120b":      (117, 5.1),
    "Qwen3-235B-A22B":   (235, 22),
    "DeepSeek-V3/R1":    (671, 37),
    "Kimi K2":           (1000, 32),
    "밀집 70B (비교용)":   (70, 70),
}
print(f"{'모델':18s} {'4비트 가중치':>10s} {'토큰당 연산':>12s} {'활성 비율':>8s}")
for name, (total, active) in models.items():
    mem_gb = total * 4.5 / 8                      # 모든 전문가를 메모리에 올려야 함
    gflop = 2 * active                            # 토큰당 약 2 × 활성 파라미터 FLOP
    print(f"{name:18s} {mem_gb:8.0f} GB {gflop:9.0f} GFLOP {active / total:8.1%}")
```

Kimi K2(1조 개)는 4비트로도 가중치만 **562GB**라 GPU 여러 장이나 대용량 메모리 서버가 필요하지만, 토큰당 연산은 64 GFLOP으로 **밀집 70B 모델(140 GFLOP)의 절반**도 안 됩니다. 활성 비율이 3–10%에 불과하기 때문입니다. 즉 MoE는 "메모리는 많이, 계산은 적게" 쓰는 구조입니다. gpt-oss-120b는 66GB로 80GB GPU 한 장이나 고메모리 PC에 들어가면서 토큰당 연산은 10 GFLOP에 불과해, 로컬에서 큰 모델을 쓰려는 사람들에게 인기가 높습니다. 디코딩 속도는 [대역폭이 정하므로](../systems/inference.md) 실제로는 활성 파라미터를 읽는 양(5.1B × 4.5비트 ≈ 3GB)이 속도를 좌우합니다.

??? expert "전문가 노트 — 라이선스 읽기, 안전 논쟁, 모델 고르기"
    **라이선스를 꼭 읽자.** "오픈"이라는 말만 믿고 상용 서비스에 쓰면 곤란해질 수 있습니다. 확인할 점: ① 상업적 사용 허용 여부와 조건(월간 사용자 수 상한 등), ② 다른 모델 학습에 출력 사용 금지 조항, ③ 수정본 배포 시 이름·표기 의무, ④ 허용 용도 정책, ⑤ 특정 지역·기업에 대한 제한. Apache 2.0·MIT는 가장 자유롭고, 회사별 커스텀 라이선스는 조건이 제각각입니다.

    **오픈 웨이트와 안전.** 가중치가 공개되면 안전 학습을 미세 조정으로 쉽게 되돌릴 수 있고, 회수도 불가능합니다. 그래서 위험 능력(생물·사이버)이 일정 수준을 넘는 모델의 공개를 두고 논쟁이 계속됩니다. 찬성 측은 투명성, 연구 접근성, 권력 집중 방지, 독립적 안전 연구를 근거로 들고, 신중론 측은 오용 위험과 비가역성을 듭니다. 일부 개발사는 공개 전 "악의적 미세 조정" 시나리오로 위험 능력을 평가해 결과를 공개합니다 → [정렬과 AI 안전](../society/safety.md). EU AI Act는 오픈소스 모델에 일부 의무를 면제하지만 시스템적 위험 모델은 예외로 둡니다 → [AI 규제](../society/regulation.md).

    **모델 고르기.** ① 하드웨어로 크기 상한을 정하고(→ [로컬 LLM 실행](../practice/local-llm.md)), ② 용도에 맞는 계열(코딩, 다국어, 비전, 추론)을 고르고, ③ 공개 리더보드는 참고만 하고 **내 과제의 평가 세트**로 2–3개 후보를 비교하고, ④ 라이선스를 확인합니다. 한국어 과제는 영어 점수와 순위가 크게 다를 수 있으므로 반드시 한국어로 평가하세요.
